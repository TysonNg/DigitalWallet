# Frontend internationalization

UI routes always use /vi or /en. The URL wins NEXT_LOCALE; unprefixed URLs use a valid cookie or vi. Browser language is deliberately ignored. Auth remains a landing-page popup.

Set SITE_URL to the public origin in production for canonical URLs and sitemap. Default development origin: http://localhost:3000.

Translation source files live in messages/vi and messages/en. Run pnpm messages:check to merge and verify identical keys. Commit both source namespaces and generated vi.json/en.json. Build runs this check automatically.

Run pnpm test:i18n, pnpm exec tsc --noEmit, pnpm lint and pnpm build.

Backend messages, notification content, transaction descriptions and emails are intentionally preserved. Language selection never changes wallet currency or business validation rules.

## Authenticated dashboard requests

The dashboard reads the session during SSR, then loads wallet and notification data through client-invoked Server Actions. Do not prefetch these actions during Server Component rendering: a refresh rotates the backend token and must persist the new BFF session cookie in a writable response context.

Refresh requests share a token exchange within one BFF process; successful pairs are retained for 30 seconds to cover concurrent requests carrying the previous cookie. Each action persists the pair in its own response. Multiple BFF replicas require shared server-side session/rotation coordination before scaling out. Only definitive authentication rejection clears the session; temporary failures remain retryable.

Run `pnpm test:auth` for refresh coordination and session persistence regression tests. Existing stale cookies from a failed rotation may require logging in again once.
