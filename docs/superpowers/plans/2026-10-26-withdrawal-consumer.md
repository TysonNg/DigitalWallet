# Withdrawal Kafka Consumer Implementation Plan

Goal: Kafka triggers existing payout processing, with durable shared inbox receipts, retry/DLT and safe scheduler handoff. No commits or live provider calls.
Architecture: Listener validates envelope then calls application ConsumeWithdrawalEventUseCase. Application locks consumer+event using existing watchdog Redis lock, checks completed receipt and current withdrawal state, invokes existing process use case outside a surrounding DB transaction, and writes a completed inbox receipt in its own transaction. There is intentionally no in-progress receipt or lease: failed processing is retryable; crash after processing is replayed using withdrawal state, Redis withdrawal lock and stable provider keys/checkpoints. Inbox does not claim exactly-once provider execution.
Persistence: generic inbox_event table with composite primary key (consumer_name,event_id), aggregate_id and processed_at, JPA entity/mapper/SpringData repository/adapter; application port has no Kafka dependency.
Handoff: withdrawal.processing-mode selects kafka or scheduler. Kafka mode excludes fresh PENDING from reconciliation, but keeps PROCESSING, SUCCEEDED delayed return checks and legacy PENDING with provider checkpoints/UNKNOWN attempt. Process use case commits PROCESSING before external calls so any interrupted start becomes recovery work. Webhook inbox reconciliation remains unchanged. Old running scheduler workers must be stopped when switching modes; legacy fresh PENDING without an outbox event requires explicit backfill/recovery, never silently start from scheduler.
Consumer: dedicated Boot-configured factory, RECORD ack, auto-commit false, max.poll.records=1, max.poll.interval.ms=600000. DefaultErrorHandler retries temporary failures; InvalidWithdrawalEventException skips retries. DeadLetterPublishingRecoverer requires successful broker acknowledgement before recovery/offset advance. DLT has at least source partition count. DLT does not refund or mark inbox complete. Native queries remain inside Spring Data.
