# Generic Outbox Publisher Implementation Plan

Goal: Publish shared outbox events to Kafka with acknowledgement, persisted retry and concurrent-worker safety. Keep existing withdrawal scheduler and do not commit.
Architecture: Infrastructure-only delivery components; JPA repository selects one due unpublished row using PostgreSQL FOR UPDATE SKIP LOCKED. TransactionTemplate REQUIRES_NEW holds that row until broker acknowledgement and delivery metadata commit. Each poll processes at most batch-size rows, one transaction per event. No leases or migration required. Kafka sender resolves destination via existing spring.kafka.topics and emits a versioned JSON envelope keyed by aggregateId. Failure persists capped exponential backoff; late/unknown acknowledgement remains retryable. No strict ordering across workers/retries is promised.
Tech stack: Existing Spring Data JPA, Spring Kafka, PostgreSQL and JUnit4.

Choices: spring.kafka.outbox is an application extension alongside topics/groups. Default enabled in application.yaml; config class only registers worker/scheduler when explicitly enabled. Retry indefinitely with capped delay, no automatic deletion/DLT. attempts counts failed attempts; success clears last_error. last_error/logs include exception class only, no payload/secret. Hold only an outbox row lock, never a wallet lock while waiting for Kafka. Producer max.block.ms and delivery.timeout.ms are bounded; ack-timeout separately bounds future wait. Shutdown interrupts preserve retryability and interrupt flag. Scheduler gets a dedicated single-thread TaskScheduler so Kafka delays do not block existing reconciliation schedulers. If delivery metadata commit fails, propagate and retry on the next poll; never swallow DB failures as send errors.
